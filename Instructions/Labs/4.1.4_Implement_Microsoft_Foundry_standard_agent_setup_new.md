# AI Ready Manage hands-on exercise: Implement Microsoft Foundry standard agent setup

## Background information
Foundry Agent Service enables creating AI agents through a two-step flow: first establishing an agent environment, and then creating and configuring the agent using an SDK or the Azure Foundry portal.

Agents are always created within a Foundry project, which functions as an isolated workspace. Agents within the same project share access to file storage, conversation history, and search indexes. Data is isolated across projects, and agents cannot access resources outside their own project. Projects are the unit of sharing and isolation within Foundry.

Foundry supports three environment configuration modes that balance speed, control, and security:
- Basic setup prioritizes rapid onboarding and uses platform-managed storage for agent state. It is compatible with OpenAI Assistants and provides the same core tools and capabilities, with added support for non-OpenAI models and integrations such as Azure AI Search and Bing.
- Standard setup builds on the Basic setup by using customer-owned Azure resources for all agent data. This provides full ownership and control over files, conversation history, and vector data, and supports enterprise compliance and governance requirements.
- Standard setup with network isolation extends the Standard setup by allowing the environment to operate entirely within a customer-managed virtual network, enabling strict control over data movement and enhanced protection against data exfiltration.

The Standard agent environment is designed for enterprise-grade security, compliance, and data governance. All agent state is stored in customer-owned Azure resources, specifically Azure Storage for file uploads and intermediate system data, Azure AI Search for vector indexes used in search and retrieval, and Azure Cosmos DB for NoSQL for conversation history, system messages, and agent metadata. This ensures that all data generated during agent configuration and user interaction remains fully under the customer’s control.

Azure Cosmos DB for NoSQL used with the Standard setup must support a minimum total throughput of 3000 RU/s, in the provisioned throughput or serverless mode. Multiple containers are used to separate end-user conversations, internal system messages, and agent metadata such as instructions, tools, and configuration details.

To control how these customer-owned resources are associated with a Foundry account and project, Microsoft Foundry leverages configuration constructs known as capability hosts. Capability hosts constitute a configuration context that describes how agents operate and where their state is stored. At the account level, a capability host designates that the account is configured to use the Agents capability. At the project level, a capability host captures project-specific settings, such as agent state management. This defines whether the project uses platform-managed, multitenant storage or customer-owned, Azure resources such as Azure Storage, Azure Cosmos DB, and Azure AI Search. In Standard configurations, the project capability host defines the binding between the project and these customer-managed resources.

Capability hosts are immutable once created. They cannot be modified after provisioning, so, effectively, changes to the storage model or resource associations require deleting and reprovisioning the capability host.

Provisioning standard environments is not available directly from the Microsoft Foundry portal, but you can implement them either programmatically or via deployment templates. Sample Azure Resource Manager and Bicep templates are available from the [foundry-samples GitHub repository](https://github.com/azure-ai-foundry/foundry-samples/blob/main/infrastructure/infrastructure-setup-bicep/43-standard-agent-setup-with-customization/). They allow you to automatically create a Foundry account and project, deploy a model, and configure authentication using Managed Identity. With the Standard configuration option, you can choose between automatic provisioning of the required Azure resources or referencing pre-provisioned resources via template parameters, giving you full control over how Azure Storage, Azure Cosmos DB, and Azure AI Search are connected to your project.

## Scenario
Your company is building a centralized AI platform on Microsoft Foundry to support enterprise knowledge management and decision support across multiple business units. The platform will enable intelligent document retrieval, automated analysis of internal reports, and conversational insights for employees, with strict controls on data ownership and compliance. To ensure operational resilience and control over critical information, the team will deploy a Standard agent environment where customer-owned Azure Storage, Azure Cosmos DB, and Azure AI Search resources are used to store documents, conversation history, and search indexes. The deployment will be performed using template-based methods that reference the pre-provisioned resources. The deployment will integrate these resources with a Foundry account and project, and configure an agent model to leverage them, providing a controlled, secure, and centralized foundation for AI-driven services that can scale across the organization.

## Prerequisites
- **Azure subscription**: If you don't have an Azure subscription, [create a free account](https://azure.microsoft.com/free/) before you begin.
- **Permissions**: To create Azure AI Services resources, you should have the Owner role assigned at the Azure subscription.
- **Familiarity with Microsoft Foundry resource types**: To learn more, refer to [Choose an Azure resource type for AI foundry](https://learn.microsoft.com/en-us/azure/ai-foundry/concepts/resource-types).

## Estimated duration
25 minutes

### Task 1: Provision an Azure Storage account for BYO file storage

1. Start a web browser, navigate to the Azure portal at [https://portal.azure.com](https://portal.azure.com) and sign in by providing the credentials of a user account which has the Owner role assigned at the Azure subscription level.
1. In the web browser displaying the Azure portal, use the **Search** text box at the top of the page to search for **Storage accounts** and, in the list of results, select **Storage accounts**.
1. On the **Storage accounts \| Storage accounts (Blobs)** page, select **+ Create**.
1. On the **Basics** tab of the **Create storage account** page, specify the following settings (leave others with their default values) and select **Next**:

   |Setting|Value|
   |---|---|
   |Subscription|The name of the Azure subscription you are using in this exercise|
   |Resource group|The name of a new resource group **foundry-standard-agent-RG**|
   |Storage account name|Any globally unique name between 3 and 24 in length consisting of lowercase letters and digits, starting with a letter|
   |Region|The name of the Azure region which supports Microsoft Foundry standard agent setup|
   |Preferred storage type|**Azure Blob Storage or Azure Data Lake Storage Gen 2**|
   |Performance|**Standard**|
   |Redundancy|**Locally redundant storage (LRS)**|


   >**Note**: For the list of Azure regions to choose from, refer to the values of the **location** parameter in the [**azuredeploy.json**](https://github.com/azure-ai-foundry/foundry-samples/blob/main/infrastructure/infrastructure-setup-bicep/41-standard-agent-setup/azuredeploy.json) Azure Resource Manager template. Verify that you can provision an Azure AI Search instance and Azure Cosmos DB account in the same region.

1. On the **Advanced** tab, specify the following settings (leave others with their default values) and select **Next**:

   |Setting|Value|
   |---|---|
   |Enable storage account key access|**Disabled**|

1. On the **Networking** tab, ensure that the **Public network access** option is set to **Enable**, the **Public network access type** is set to **Enable from all networks**, and then select **Review + create**.
1. On the **Review + create** tab, wait for the validation process to complete, and then select **Create**.

   >**Note**: Wait for the resource provisioning to complete. This should take less than one minute. 

1. On the **Deployment** page, select **Go to resource**.
1. On the **Overview** page of the newly provisioned storage account, in the upper right corner, select **JSON View**.
1. On the **Resource JSON** pane, select the copy icon in the **Resource ID** text box. 

   >**Note**: Record the value of the Resource ID of the storage account (for example by pasting it into Notepad). You'll need it later in this exercise.

### Task 2: Provision an Azure AI Search instance for BYO search

1. In the web browser displaying the Azure portal, use the **Search** text box at the top of the page to search for **AI Search** and, in the list of results, select **AI Search**.
1. On the **Microsoft Foundry \| AI Search** page, select **+ Create**.
1. On the **Basics** tab of the **Create search service** page, specify the following settings (leave others with their default values) and select **Next: Scale**:

   |Setting|Value|
   |---|---|
   |Subscription|The name of the Azure subscription you are using in this exercise|
   |Resource group|**foundry-standard-agent-RG**|
   |Service name|**foundrystdsearch**|
   |Location|The name of the same Azure region you specified when provisioning the storage account earlier in this exercise|
   |Pricing tier|**Free**|

   >**Note**: In real-world scenarios, you should consider using at least the **Standard** pricing tier.

1. On the **Scale** tab of the **Create search service** page, accept the default settings and select **Review + create**.
1. On the **Review + create** tab, wait for the validation process to complete, and then select **Create**.

   >**Note**: Wait for the resource provisioning to complete. This should take less than one minute. 

1. On the **Deployment** page, select **Go to resource**.
1. On the **Overview** page of the newly provisioned AI Search resource, in the upper right corner, select **JSON View**.
1. On the **Resource JSON** pane, select the copy icon in the **Resource ID** text box. 

   >**Note**: Record the value of the Resource ID of the AI Search resource (for example by pasting it into Notepad). You'll need it later in this exercise.

### Task 3: Provision an Azure Cosmos DB account for BYO thread storage

1. In the web browser displaying the Azure portal, use the **Search** text box at the top of the page to search for **Azure Cosmos DB** and, in the list of results, select **Azure Cosmos DB**.
1. On the **Azure Cosmos DB** page, select **+ Create**.
1. On the **Create an Azure Cosmos DB account** page, on the **Recommended APIs** tab, on the **Azure Cosmos DB for NoSQL** tile, select **Create**.
1. On the **Basics** tab of the **Create Azure Cosmos DB Account - Azure Cosmos DB for NoSQL** page, specify the following settings (leave others with their default values) and select **Next: Global distribution**:

   |Setting|Value|
   |---|---|
   |Workload Type|**Learning**|
   |Subscription|The name of the Azure subscription you are using in this exercise|
   |Resource group|**foundry-standard-agent-RG**|
   |Account name|**foundrystdthreads**|
   |Availability Zones|**Disable**|
   |Location|The name of the same Azure region you specified when provisioning the storage account earlier in this exercise|
   |Capacity mode|**Serverless**|

1. On the **Global distribution** tab, review its settings without making any changes and then select **Next: Networking**.

   >**Note**: The serverless capacity mode does not support geo-redundancy and multi-region writes.

1. On the **Networking** tab, ensure that **Connectivity method** is set to **All networks** and then select **Next: Backup policy**.
1. On the **Backup policy** tab, specify the following settings (leave others with their default values) and select **Next: Security**:

   |Setting|Value|
   |---|---|
   |Backup interval|**24 Hour(s)**|
   |Backup retention|**2 Day(s)**|
   |Backup storage redundancy|**Locally-redundant backup storage**|

   >**Note**: In production environments, you should adjust these values to reflect the intended level of resiliency.

1. On the **Security** tab, set **Key-based Authentication** to **Disabled** and then select **Review + create**.
1. On the **Review + create** tab of the **Create Azure Cosmos DB Account - Azure Cosmos DB for NoSQL** page, wait for the validation process to complete, and then select **Create**.

   >**Note**: Wait for the resource provisioning to complete. This might take about 2 minutes.

1. On the **Deployment** page, select **Go to resource**.
1. On the **Overview** page of the newly provisioned Azure Cosmos DB account, in the upper right corner, select **JSON View**.
1. On the **Resource JSON** pane, select the copy icon in the **Resource ID** text box. 

   >**Note**: Record the value of the Resource ID of the Azure Cosmos DB account (for example by pasting it into Notepad). You'll need it later in this exercise.

### Task 4: Deploy a Microsoft Foundry standard agent by using a template

1. In the web browser displaying the Azure portal, open another tab and browse to the standard agent deployment Bicep template **README.md** page in the [foundry-samples GitHub repository](https://github.com/azure-ai-foundry/foundry-samples/blob/main/infrastructure/infrastructure-setup-bicep/43-standard-agent-setup-with-customization/).
1. On the **Azure AI Foundry Agent Service: Standard Agent Setup with Public Networking & Additional Customization** page, select **Deploy to Azure**. This will automatically open the **Custom deployment** page in the Azure portal.
1. On the **Custom deployment** page, specify the following settings (leave others with their default values) and select **Review + create**:

   |Setting|Value|
   |---|---|
   |Subscription|The name of the Azure subscription you are using in this exercise|
   |Resource group|**foundry-standard-agent-RG**|
   |Region|The name of the same Azure region you specified when provisioning the storage account earlier in this exercise|
   |Location|The name of the same Azure region you specified when provisioning the storage account earlier in this exercise|
   |AI Foundry name|**foundrysa**|
   |Project name|**foundrysaproject**|
   |Project description|**foundry standard agent**|
   |AI Search Resource id|The resource id of the pre-provisioned Azure AI Search resource you recorded earlier in this exercise|
   |Azure Storage Account Resource id|The resource id of the pre-provisioned Azure Storage account you recorded earlier in this exercise|
   |Azure Cosmos DB Account Resource id|The resource id of the pre-provisioned Azure Cosmos DB account you recorded earlier in this exercise|
   |Azure Aoai Resource id|Leave blank|
   |Project Cap Host|**caphostsaproject**|
   |Account Cap Host|**caphostsaaccount**|

1. On the **Review + create** tab of the **Custom deployment** page, review the configuration settings and then select **Create**.

   >**Note**: Wait for the template deployment to complete. This might take about 5 minutes.

### Task 5: Review the deployment results

1. In the web browser displaying the Azure portal, on the **Deployment** page, select **Go to resource group**.
1. On the **foundry-standard-agent-RG** page, review the list of resources, including a Microsoft Foundry resource and its default project, along with the three pre-provisioned resources. 
1. In the list of resources, select the Foundry project entry and, on the page displaying the project's properties, select **Go to Foundry portal**. This will display the project's **Home** page in the Microsoft Foundry portal.
1. On the project's **Home** page, in the upper-right corner, select **Operate** and then, in the vertical menu of the left side, select **Assets**.
1. On the **Assets** page, select the **Tools** tab and, in the **Project: All projects** drop-down list, clear the **All projects** checkbox and select the **foundrysaproject** entry.
1. Verify that the resulting list consists of three entries, representing the pre-provisioned Azure Storage account, Azure AI Search instance, and Azure Cosmos DB account.
1. Switch to the tab displaying the Azure portal and navigate to the page displaying properties of the Azure Storage account you provisioned earlier in this exercise. 
1. On the Azure Storage account page, in the vertical menu on the left side, expand the **Data storage** section and select **Containers**.
1. Review the list of containers and verify that it includes two auto-generated containers, which names end, respectively, with **-azureml-agent** and **-azureml-blobstore**.
1. In the web browser displaying the Azure portal, navigate to the page displaying properties of the Azure Cosmos DB account you provisioned earlier in this exercise. 
1. On the Azure Cosmos DB account page, in the vertical menu on the left side, select **Data Explorer**.
1. Review the list of databases and containers and verify that the list includes the **enterprise_memory** database with four containers, which names end, respectively, with **-agent-definitions**, **-agent-entity-store**, **-system-thread-message-store** and **-thread-message-store**.

### Task 6: Perform cleanup

1. On the **foundry-standard-agent-RG** page, select **Delete resource group**, on the **Delete a resource group** pane, in the **Enter resource group name to confirm deletion** text box, enter **foundry-standard-agent-RG**, select **Delete**, and, when prompted for confirmation, select **Delete** again.
